# Tasks — add-inventory-assistant (S7)

Tier A. `[MUT]` declarados: 9 (M1–M9): solo lectura de las herramientas (M1, M2), rol en la herramienta (M3),
exclusión de datos de pacientes (M4, M5), defensa contra inyección (M6, M7), ciclo acotado (M8), honestidad del
reporte de evaluación (M9). Borrador del spec-engineer, refinado por el architect contra `design.md` (D1–D15): `answer`
compuesto por el servidor (D8), base efímera de evaluación (D14), solo lectura por punto de guardado (D5).
Requisito previo técnico: S1–S5 archivados (capacidades y Gates, forma de rechazo D5, `SpaClient`,
`BusinessCalendar`, consultas de existencias y de alertas, traslados con `notes`). Orden de ROADMAP: apply tras
archivar S6.
Bloques: api (1–6) → devops (7) → documentación (8) → cierre (9). Sin `web`: el panel en la SPA queda fuera
(proposal, supuesto 1). Paralelo permitido (sin contrato de API entre ellos): 4.2 (Ollama) tras 1.1, en paralelo con 2–3;
7.1 (variables en compose) en paralelo con todo el bloque api. 7.2 y 8.1 esperan a 6.3. Sin migraciones ni escritura de stock: sin tareas de concurrencia ni idempotencia.
Pruebas: Pest contra PostgreSQL, nunca SQLite; `Http::preventStrayRequests()` en toda la suite del asistente;
un proveedor guionado de prueba (doble de la interfaz de proveedor) simula el modelo comprometido, el bucle y
la respuesta inventada; el proveedor simulado real (`mock`) se prueba como tal, nunca sustituido.
Escenarios citados como «Requisito: escenario» de `specs/inventory-assistant/spec.md` (IA) y
`specs/assistant-evaluation/spec.md` (EV). "Cimiento" = andamiaje sin escenario propio, verificado por el
comando que nombra.
