**Arnés de mutantes** (bash, desde la raíz del repo). Con el árbol de la tarea ya confirmado en git, el implementador
escribe un parche por mutante en `openspec/changes/add-alerts/mutants/M<n>.patch`. Cada parche es el diff de una sola
costura con el texto exacto que nombra la tarea. Aplicar = `git apply`; revertir = `git apply -R`. El auditor rehace
cualquier fila con el mismo comando. `--fail-on-empty-test-suite` (PHPUnit 13.4) hace que un filtro que no casa
ninguna prueba salga distinto de 0: un filtro mal escrito nunca da un falso PASA.

```bash
pest() { docker compose -f software/compose.yaml run --rm api-tools vendor/bin/pest "tests/Feature/Alerts/$1" --filter="$2" --fail-on-empty-test-suite; }
# mut <Mn> <archivo> <filtro>: aplica, exige FALLA, revierte, exige PASA y árbol limpio. Sale 0 solo si ocurre todo.
mut() { local p="openspec/changes/add-alerts/mutants/$1.patch" k; git apply "$p" || return 2; pest "$2" "$3"; k=$?
  git apply -R "$p" || return 3; pest "$2" "$3" || return 4; git diff --quiet -- software/api || return 5; [ "$k" -ne 0 ]; }
# ctl <Mn> <archivo> <filtro>: control positivo; con el mutante aplicado el filtro PASA.
ctl() { local p="openspec/changes/add-alerts/mutants/$1.patch" k; git apply "$p" || return 2; pest "$2" "$3"; k=$?
  git apply -R "$p" || return 3; git diff --quiet -- software/api || return 5; [ "$k" -eq 0 ]; }
```
Autocontrol del arnés, una vez antes del primer `[MUT]`: `! pest AlertEndpointTest.php 'no-existe-zzz'` sale 0.
Si un acento impide que el filtro case, se sustituye por `.`. El filtro registrado en `verification.md` es el que
