# Tasks — add-operator-screens (S6)

Tier B. `[MUT]` declarados: 4 (M1–M4), solo donde una implementación perezosa pasaría las pruebas: clave por
intención reutilizada (M1), doble envío (M2), clave nueva al cambiar la intención (M3), Aprobar oculto para el
solicitante (M4). Decisiones en `design.md` (D1 tipos con `openapi-typescript`, D2 MSW, D3 clave por intención, D4 candado de
envío, D5 catálogo de errores, D6 tabla de rutas, D7 carpetas). Orden: 0 → 1 (secuencial) → 2–5 (independientes
entre sí; un solo implementador las hace en serie, Dispensación primero por peso) → 6 → 7.
Requisito previo: S1–S5 archivados. Todo es `software/web`: sin endpoints nuevos ni cambiados, por eso no hay
tareas de prueba HTTP real del backend. Un solo implementador (frontend); devops no participa.
Pruebas: Vitest + Testing Library, red simulada en el borde HTTP (nunca se simula el hook ni el componente bajo
prueba), una prueba por escenario citado. Comando: `npm --prefix software/web test -- --run` (más `run lint` y
`run typecheck`). Textos solo desde el módulo central de textos (`software/web/src/lib/strings.ts`).
Escenarios citados como «Requisito: escenario» de `specs/<capacidad>/spec.md`. "Cimiento" = andamiaje sin
escenario propio, verificado por el comando que la tarea nombra.
